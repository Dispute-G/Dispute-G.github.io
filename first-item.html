Первое добавление предмета

Подготовка проекта

Когда вы зайдёте в скачанный MDK, вы увидите подобный путь:

Learning\src\main\java\com\asrug\learning_mod

В нём будет ряд классов с созданными заранее предметами. Я бы рекомендовал, чтобы сначала не забивать голову, удалить все классы кроме "ExampleMod".

В нём тоже сотрите всё и оставьте:

ExampleMod.java (в данном случае LearningMod.java)

Пойдём по порядку:

  • package com.asrug.learning_mod; - путь до основного класса, в котором вы сейчас находитесь
  • import net.neoforged.fml.common.Mod; - импортирование аннотации @Mod, она обязательна для отметки главного класса мода. В неё передаётся константа ID вашего мода, которую вы создадите далее
  • LearningMod - название основного класса мода
  • public static final String MODID = "learning_mod"; - создание константы ID вашего мода, далее вы будете её часто использовать

Структурирование проекта

Теперь перейдём к самому созданию предмета. Начнём с основного - структурирование проекта.

💡 Важно: Учитесь сразу избегать скопления кода в одном месте. Разбивайте конкретную тему по отдельным классам.

Для начала создадим такой путь:

Learning\src\main\java\com\asrug\learning_mod\items

В нём создадим класс ModItems - он будет служить нам основным классом для добавления предметов.

Добавление простого предмета

Начнём с добавления простых предметов без каких-то встроенных в них эффектов, кастома и прочего. Просто предмет с текстурой.

Добавление такого предмета выглядит так:

ModItems.java

Разбираем по порядку:

1. Регистр предметов

Создание регистра

DeferredRegister - это список дел для регистрации при загрузке мода. Конкретно для предметов используется Items.

2. Регистрация предмета

Добавление предмета

Здесь мы очень быстро добавляем предмет ruby в указанный выше список.

3. Метод регистрации

Метод register

Это метод, чтобы вызвать саму регистрацию предметов. Его мы вызовем в дальнейшем в основном классе.

Подключение к основному классу

Теперь возвращаемся к основному классу:

LearningMod.java (обновлённый)

Что здесь происходит:

  • public LearningMod - конструктор класса (об этом подробнее в обучении Java)
  • IEventBus modEventBus - шина событий, нужна, чтобы зарегистрировать наши объекты в нужный момент
  • ModItems.register(modEventBus) - это вызов метода, который мы создали в ModItems
✅ Готово! Таким образом мы создаём предмет ruby. Внутреннее имя будет learning_mod:ruby, где первое - ID мода, второе - название предмета, которое мы указали выше.

Проверка в игре

Если мы зайдём в игру и напишем /give @p learning_mod:ruby, мы получим стак нашего предмета. Он уже будет существовать в игре, но будет иметь "шахматку" - так называется фиолетово-чёрная текстура, обозначающая отсутствие таковой.

Добавление текстуры

Для придания текстуры потребуются две вещи - файл модели и сама текстура. Так как мы не придавали никаких уточнений в предмете, NeoForge будет искать их в путях по умолчанию.

Модель предмета

Путь: Learning\src\main\resources\assets\learning_mod\models\item

В нём создаём файл ruby.json, в котором указываем:

ruby.json
  • "parent": "minecraft:item/generated" - это использование стандартного 2D-спрайта предмета
  • "textures" - какие текстуры использовать
  • "layer0" - основной слой текстуры
  • "learning_mod:item/ruby" - путь к текстуре (автоматически добавляется .png)

Текстура предмета

Дальше по пути Learning\src\main\resources\assets\learning_mod\textures\item мы добавляем .png текстуру предмета.

✅ Всё! Это основное, чтобы наш предмет просто был и чтобы имел корректную текстуру, которую вы сами захотите.

Важные уточнения

1) Локализация (перевод названия)

Используйте файл локализации - это .json файл, чтобы вы могли поменять внутреннее имя предмета на то, которое сами захотите. Для англоязычной локализации используйте en_us.json, для русской ru_ru.json.

Путь: Learning\src\main\resources\assets\learning_mod\lang

В нём пишем:

ru_ru.json

И тем самым мы получим предмет уже не с именем item.learning_mod.ruby, а просто Рубин.

2) Анимационная текстура

Далее, если вы хотите создать анимационную текстуру, её нужно поменять и добавить файл .mcmeta.

По порядку:

Сама текстура должна быть разбита на кадры, идущие сверху вниз. То есть, если вы хотите три кадра, а текстура у вас 16×16, то вы делаете её 16×48 (48 по вертикали!), тем самым разбиваете текстуру на три участка 16×16, в каждой размещая свой кадр.

Далее вы создаёте новый файл с таким названием: ruby.png.mcmeta. То есть, берёте прям название вашей текстуры и добавляете .mcmeta (не удаляете вашу текстуру! Создаёте новый файл!).

В нём пишите:

ruby.png.mcmeta (автоматическое переключение)

Это автоматическое переключение между вашими кадрами, начиная с верхнего каждые 20 тиков (1 секунда). Вы можете менять значение тиков как захотите.

Если вы хотите своё кастомное переключение кадров, то пишите:

ruby.png.mcmeta (кастомная раскадровка)

Где frames - это список из раскадровки, в каком порядке им идти, где 0 - это первый кадр текстуры.

🎉 Вот и всё, ваш первый предмет готов!
